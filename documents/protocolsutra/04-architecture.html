Design goals

  1. Offline and deterministic. Same input, same output, same digest.
  2. Zero runtime dependencies. Node.js built-ins only, so the supply-chain surface is the project itself.
  3. Pure core, thin shell. Evaluation logic is pure functions over parsed JSON; file and network I/O lives only in the CLI, installer and server.
  4. Honest states. The type of every verdict carries its evidence class.

Data flow

captured JSON (snapshot / card / suite / evidence / policy+call)
        |
        v
  readJSON  --->  evaluator (pure)  --->  sanitize (redact)  --->  report model
                                                                     |
                                   +-------------+-------------------+
                                   v             v                   v
                                 JSON          Markdown        self-contained HTML
                                   |
                                   +--> capsule (digest/HMAC)  --> verify
                                   +--> gate (worst result wins) --> CI exit code

Key decisions (ADR summary)

#DecisionWhyConsequence
1Plain ESM .mjs, no build stepRuns from a clean checkout; nothing to compile or trustNo static types yet; JSON Schemas and tests carry the contract
2Canonical JSON before hashingKey order must not change a digestDigests are stable across tools and machines
3Worst result wins in the gateA blocking failure must not be averaged awayConservative: one INCONCLUSIVE blocks a GO
4Missing observation is INCONCLUSIVEAbsence of evidence is not a passMore INCONCLUSIVE results, fewer false confidences
5Snapshot format is ProtocolSutra's ownWire capture needs a live runner that is not built yetReports state clearly it is not conformance
6Policy ignores tool annotationsA server must not authorise itselfreadOnlyHint is reported but never trusted
7HMAC, not public-key signaturesNo key management in an offline toolIntegrity only; sharing the key shares signing power
8HTML reports have no script and a restrictive CSPReports contain untrusted tool textStatic tables, no sorting widgets
9Static URL screening onlyDNS resolution needs network accessRuntime must re-check resolved IPs

Trust boundaries

Everything read from a snapshot, card, trace or call is untrusted data. It is parsed, bounded (depth, array length, string length, tool count) and escaped on output. It is never executed, evaluated or used to select a file path.

Extension points (planned)

  • A live MCP/A2A runner that produces the same report shape (executedLive: true).
  • SARIF export for code-scanning dashboards.
  • Official SDK/TCK result importers.

These are roadmap items, not shipped features. See Roadmap.
